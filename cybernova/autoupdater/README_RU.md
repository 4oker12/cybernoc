# Cybernova Auto Updater v1.1 — 30 секунд / 24 часа / остановка и отчёт

**Назначение.** Обновлять существующий Cybernova Agent на Vast из `4oker12/cybernoc`, ветка `cybernova-autodeploy`, исходники `cybernova/v10`. Первый новый коммит, *меняющий именно исходники агента после первоначальной фиксации baseline*, запускает окно 24 часа. По истечении 24 часов проверка прекращается. Интервал проверки во время ожидания — **30 секунд** (во время тестирования следующий опрос выполняется после завершения текущей операции; одновременно две установки не запускаются).

**Отказоустойчивость и остановка.** Любая ошибка проверки Git, не-fast-forward история, сбой тестов, установка или отправка отчёта переводят процесс в `stopped_error`. При ошибке **нет автоматического отката**: пользователь выбрал «остановка и отчёт». Если ошибка до активации — старый релиз остаётся рабочим. При ошибке после активации — новый релиз остаётся установленным для исследования; предыдущий физически хранится. При успехе выполняются тесты *до* и *после* переключения активной версии.

**Отчёты.** Всегда создаются локальные JSON-отчёты в `/workspace/cybernova-updater/reports`. Для отправки отчётов в **GitHub Issues** требуется отдельный **fine-grained access token, ограниченный одним репозиторием и доступом Issues: read/write**. Токен помещается самим оператором в файл с режимом 0600, например `/workspace/cybernova-updater/secrets/github-issues-token`, и в `config.json` задаются `github_reporting: true` и `github_issue_token_file: <путь>`. Это НЕ тот же доступ, что SSH Deploy key на чтение кода. Если токена нет, `github_reporting` оставляют false: локальные отчёты работают, но на GitHub не публикуются. Не присылайте токен в чат и не добавляйте его в Git.

## Архитектура

```
ChatGPT -> commit in cybernova-autodeploy
              |
      git@github.com (read-only Deploy key)
              |
   cybernova-updater (non-root user cybernova)
       poll 30 sec | session 24h
       pinned SHA + only subtree cybernova/v10
              |
    release staging -> unittest -> managed current symlink -> unittest
              |
      persistent reports -> optionally GitHub Issues
          success: continue; failure: stop+report
```

Никаких произвольных shell-строк из Qwen, загрузки произвольных URL, `pip install` или `apt` этот наблюдатель не выполняет. Git-атрибуты/ссылки архива проверяются. GitHub SSH-host key предзаписан из официальной публикации GitHub. Старые релизы и история заданий не удаляются. Тесты из доверенной ветки GitHub всё равно **исполняют код**; нужен отдельный непривилегированный пользователь с минимальным доступом к системе. Выдавайте права записи в эту ветку только доверенным участникам. Защита тестов на уровне контейнерного sandbox не реализована.

## Первоначальное развёртывание на Vast

Пока **НЕ УСТАНОВЛЕНО** — код опубликован для установки. Для однократной активации на сервере:

1. Доставить исходники этого каталога (`cybernova/autoupdater` в ветке `cybernova-autodeploy`) на Vast и запустить один раз `bash install.sh` от оператора. Установщик создаёт системного пользователя `cybernova`, SSH-ключ для чтения, известный ключ хоста GitHub, `/workspace/cybernova-updater`; переносит существующий `/workspace/cybernova-agent` в постоянный каталог и делает ссылку. Данные `jobs`/`operations`/`history` мигрируют в `/workspace/cybernova-updater/data/`. Ollama, веса и MCP-туннель не меняются. Существующие задачи агента должны быть остановлены до миграции.
2. Скопировать **только публичный ключ**, который вывел установщик, в [Deploy keys](https://github.com/4oker12/cybernoc/settings/keys) и оставить **Allow write access** выключенным. Приватный ключ остаётся на Vast.
3. Запустить `bash start_daemon.sh` (от оператора) из того же каталога. Скрипт проверяет доступ к GitHub, запускает фоновую службу под `cybernova` и, если доступен cron, добавляет `@reboot` для восстановления процесса после перезагрузки Vast.
4. Если нужны **именно GitHub Issues** с отчётами, отдельно выдать fine-grained Issues token (только для cybernoc, Issues: write), записать его приватно на Vast, поставить `github_reporting=true` в `config.json` и перезапустить watcher после очистки ошибок. Не отправлять секрет в сообщения.

Внимание: настройка пользователя, миграция старой директории и установка службы — одноразовые системные операции; текущий MCP `terminal_execute` требует локального подтверждения. Полные разрешения ChatGPT сами по себе не дают возможности запускать этот bootstrap. До этого момента реальный 24-часовой процесс на Vast не запущен.

## Проверка

```
cd cybernova/autoupdater
PYTHONPATH=. python3 -m unittest discover -s tests -v
python3 -m compileall -q cybernova_updater
```

Проверены: baseline, изменение вне `cybernova/v10`, первый кодовый коммит, повторный коммит, сохранение времени окончания, отсутствие повторных установок, истечение ровно 24 часов, сбой теста, сетевой сбой, принудительный force-push, ошибка доставки отчёта, защита SSH, отказ от symlink-выхода, восстановление после прерывания и реальные Git clone/fetch/archive в изолированном тесте.

Состояние: `/workspace/cybernova-updater/state.json`, журналы: `/workspace/cybernova-updater/runner.log`, отчёты: `/workspace/cybernova-updater/reports/*.json`. Для просмотра: `runuser -u cybernova -- env PYTHONPATH=/workspace/cybernova-updater/app python3 -m cybernova_updater.cli --config /workspace/cybernova-updater/config.json status`.

**Тайминг**: ожидание 30 секунд между опросами. 24 часа начинаются не с даты любого старого коммита в GitHub, а со времени обнаружения первого **нового коммита исходников**. Если во время установки идут тесты дольше 30 секунд, пропущенные проверки не наслаиваются. После завершения режима служба прекращает опрос. Для новой 24-часовой сессии нужен явный сброс состояния оператором после сохранения отчётов.
