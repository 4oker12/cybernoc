# Cybernova Agent v1.0 — GitHub и локальные программы

**Назначение:** расширить набор инструментов локальной Qwen3-Coder Heretic 30B. Это обновление инструментов/контроллера, **не дообучение весов модели**.

## Новые действия Qwen

| Действие | Что делает | Что не делает |
|---|---|---|
| `repo_status {}` | Проверяет локально загруженную копию исходников Cybernova и SHA коммита | Не меняет исходники |
| `repo_sync {}` | Загружает **только** ветку `cybernova-autodeploy` приватного репозитория `4oker12/cybernoc`, проверяет origin и делает только fast-forward | Не исполняет загруженный код, не обновляет работающий MCP и не выполняет shell-команду модели |
| `install_python_tool {"name":"ruff"}` | Устанавливает закреплённую версию одобренного Python-инструмента в отдельный venv проекта | Не вызывает apt, не устанавливает системные программы, не принимает произвольное имя пакета |

Одобренные инструменты: `ruff==0.14.6`, `pytest==9.0.1`, `httpx==0.28.1`, `rich==14.2.0`.

## Изоляция

- Запуск **не от root**. Если агент ещё работает с root-правами, изменяющие операции возвращают ошибку с объяснением.
- Git и виртуальное окружение хранятся в `/workspace/cybernova-agent/operations/<project>/`, а не в каталоге проекта, где Qwen может создавать файлы.
- `repo_sync` не удаляет локальные изменения, не использует `reset --hard`, а при конфликте останавливается.
- Команды исполняются только как фиксированные аргументы `subprocess.run(..., shell=False)`; неизвестные URL, ветки и команды отвергаются.
- Для приватного GitHub на Vast нужно **один раз** настроить доступ **только на чтение**, например Deploy Key. Ключ не передавать через чат, логи и команды MCP.
- Для системных утилит/`apt` предусмотрен запрос человеку. Разрешения на установку системных программ у Qwen пока нет.

## Что ещё не настроено на Vast

Успешная локальная проверка не означает, что версия уже запущена на Vast. Чтобы Qwen реально смогла вызывать инструменты, требуется развернуть обновлённые файлы контроллера на сервере и запустить Agent **от непривилегированного пользователя**. При первом использовании приватного GitHub настроить read-only доступ. После этого Qwen выбирает инструмент самостоятельно в штатном цикле Ollama tool calling.

## Тесты

```bash
cd cybernova/v10
PYTHONPATH=. python3 -m unittest discover -s tests -v
```

Тесты покрывают запрет произвольных команд и URL, symlink/path escape, запрет установки от root, запрет неподтверждённых пакетов, проверку origin и отклонение обновления грязного репозитория, передачу инструментов модели. Проверка по GitHub и запуск на GPU отдельно будут требовать реального подключения к Vast.
