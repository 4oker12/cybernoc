## Единый интерфейс: Qwen и ChatGPT

В левом меню находятся только два режима:

- **Qwen · Исследователь** — обычная исследовательская сессия с подключёнными MCP,
  одноразовыми разрешениями, задачами и журналом доказательств. Загрузка HAR,
  PCAP и конфигураций доступна только здесь (до 50 МиБ).
- **ChatGPT · Обычный чат** — самостоятельный многоходовой разговор через
  официальный OAuth аккаунта и Responses API. Модель выбирается сверху, новая
  беседа создаётся общей кнопкой «Новый чат», прошлые диалоги открываются слева.
  Сообщения хранятся отдельно в таблицах gpt_threads/gpt_messages внутри
  приватной SQLite на Vast; обновление страницы не удаляет историю.
  **Сообщения не передаются Qwen и не запускают его MCP-инструменты.**
  В облако OpenAI отправляется только контекст выбранного GPT-диалога после
  явной отправки сообщения пользователя; не отправляются задачи Qwen,
  импортированные артефакты и история других GPT-чатов.

Подключение аккаунта вынесено в **«Аккаунт GPT»**. Необязательные действия
«Проверить исследование через GPT» и ручная рецензия свёрнуты в разделе
инструментов и не мешают переписке. Обычный чат не заменяет ChatGPT на сайте
OpenAI: память, файлы, встроенные возможности и история аккаунта оттуда не
импортируются. Наличие модели в списке — не гарантия успешного первого ответа.

**Разметка ответов:** заголовки, форматирование, списки, цитаты, code fences,
таблицы и отдельные метки «Рекомендация Qwen», «Следующий шаг» и
«Критерий успеха» отображаются без сырых Markdown-символов.
Визуализатор создаёт DOM только через textContent и строго разрешённые
HTTP(S)-ссылки; недоверенный HTML из ответов моделей не исполняется.

## Вход через ChatGPT без отдельного API-ключа

В Web UI добавлена панель **ChatGPT**: официальный OAuth Sign in with ChatGPT
(Authorization Code, PKCE, проверенный ID token), выбор GPT-модели и независимая
текстовая рецензия текущей задачи через Responses API. Результат показывается
рядом с Qwen, сохраняется в журнале и **только по отдельной кнопке** передаётся
Qwen как замечание рецензента.

Для Vast нужна доступность Web UI через локальный SSH port-forward
127.0.0.1:18795: callback OpenAI использует только loopback. Cloudflare
Quick Tunnel для входа не подходит. Подписка/клиент должны поддерживаться OpenAI:
факт реального OAuth-входа ещё не проверен, история и память ChatGPT не импортируются,
авторизация не заменяет подключение нашего кастомного MCP к данному чату.

Инструкция и границы: [SIGN_IN_WITH_CHATGPT.md](SIGN_IN_WITH_CHATGPT.md).

# Cybernova Chat Console — собственный простой чат

Отдельный интерфейс для локальной Qwen и существующего MCP gateway: список диалогов слева, переписка по центру, поле ввода снизу, результаты инструментов и предлагаемые Qwen следующие вопросы под ответом.

## Общий диалог ChatGPT ↔ Qwen (Communication Gateway)

Добавлен второй, отдельный MCP-сервис, который работает с той же постоянной
SQLite-очередью задач, что и собственный Web UI Cybernova.

- Qwen может записывать прогресс и запросы на независимую рецензию ChatGPT.
- ChatGPT через подключённый Communication MCP может получать сообщения,
  читать диалог и отправлять замечания обратно в задачу.
- На Vast работает локальный воркер, который забирает такие замечания
  из очереди, продолжает Qwen и сохраняет её ответ.
- В собственном чате добавлены сохранённые задачи, журнал гипотез и
  инструментальных отпечатков, пакет для рецензии и отображение сообщений
  ChatGPT. Закрытие браузера не удаляет текст задач из SQLite.
- MCP Gateway для инструментов на 18792 остаётся отдельным от
  Communication MCP на 18796.
- Подключение нового сервиса к обычному ChatGPT требует регистрации
  или обновления доверенного MCP-коннектора. **На данном этапе это код и
  тесты, а не подтверждённое новое подключение ChatGPT к Vast.**
- MCP не может немедленно разбудить ChatGPT: возможен ручной вызов или
  поддерживаемая периодическая проверка после подключения коннектора.

Подробная архитектура, инструкции запуска, API и сценарий испытаний:
см. COMMUNICATION.md.

## Текущий реализованный инструментарий

В собственном чате Cybernova регистрируется динамический набор MCP-функций:
удалённые функции активного MCP плюс локальные обработчики HAR/JS,
междоменные анализаторы, DNS/TLS-проверки, браузер и DevTools Network,
Google Web Research, 11 адаптеров сканеров, инвентаризация движков,
инструменты общения с ChatGPT и разработки самой Cybernova. Точное число
зависит от подключённого MCP и сборки; наличие инструмента в каталоге не означает,
что его бинарник установлен или что цель разрешена для проверки.

- **Web/API:** HAR, JS, OpenAPI, endpoint/method/field-name map, cookie flags,
  auth metadata, API graph, coverage и BOLA/IDOR/business-logic hypotheses.
- **Network/ISP:** классический PCAP IPv4/Ethernet/VLAN/TCP/UDP/ARP,
  pseudonymous flows, сетевые логи и признаки DNS/DHCP/RADIUS/PON/TLS.
- **Server/software:** Python AST, reverse proxy/SSH/K8s/Docker configs,
  npm/requirements/CycloneDX/SPDX inventory, TLS transcript.
- **Evidence:** SHA-256, исходные артефакты удаляются после извлечения
  метаданных, hypothesis-vs-verified states, интегральный офлайн-отчёт.
- **Google Web Research:** `google_search` выполняет поиск по публичной
  выдаче Google, `research_source_open` читает HTTPS-первоисточники. Запросы
  фильтруются от IP-адресов, всех доменных имён, MAC, email и секретов; результаты
  считаются недоверенными и не доказывают уязвимость.
- **Lab scanners:** Nmap, Nuclei, ZAP Baseline и Active, Nikto, testssl.sh,
  ffuf, Semgrep, Trivy, Gitleaks и Bandit. Реализованы фиксированные argv,
  валидатор lab scope, вызов без shell, таймауты, redacted findings и карточка
  одноразового разрешения. **Бинарники не считаются установленными,
  пока окружение этого не подтвердит.**

Сканерные инструменты предназначены **только для изолированной лаборатории**.
Политика по умолчанию выключена, целевых IP нет; стандартные веб-домены или
провайдерское оборудование не могут автоматически оказаться лабораторной целью.

Подготовка лаборатории, поставка движков, профили и ограничения:
см. LAB_SCANNERS.md. Это отдельный шаг от интеграции адаптеров в GitHub.
Публичный поиск и открытие источников описаны в RESEARCH_WEB.md.

**Размер вложения:** до **50 МиБ (52,4 МБ)** на файл (ранее 4 МБ).
Предел согласован между браузером, сервером и MCP-прокси. Для PCAP
Base64 увеличивает JSON-тело приблизительно на треть, поэтому отдельный
лимит транспортного запроса составляет 80 МиБ; обычные запросы и ответы
по-прежнему ограничены прежним размером. HAR обрабатывается до 12 000
записей на файл, но итоговый граф остаётся компактным. Большие файлы
анализируются локально и после извлечения метаданных не сохраняются.
Ограничения анализаторов сохраняются: PCAP — только classic Ethernet/IPv4,
а pcapng/IPv6 пока не поддерживаются. Для файлов существенно больше
50 МиБ потребуется потоковая загрузка/обработка вместо JSON в памяти.

Загрузка файлов прямо в чат: HAR, JavaScript, OpenAPI JSON, логи, конфиги,
Python, зависимости/SBOM, TLS текст и classic PCAP. Qwen самостоятельно
вызывает traffic_* и research_* инструменты, не исполняя исходный код и
не повторяя перехваченные HTTP-запросы.

**Ограничения:** JavaScript анализируется лексически, Python статически,
PCAP пока только classic Ethernet/IPv4 (не pcapng/IPv6), зависимости не
сопоставляются с актуальными CVE, а по одной HAR-сессии нельзя подтвердить
доступ к чужим данным или дефект платежной транзакции. Полноценные DAST,
CodeQL/Joern, Zeek/Suricata и интеграция прочих кандидатов из каталога
по-прежнему требуют отдельных адаптеров.

## Схема

    Браузер (SSH port-forward)
      → FastAPI 127.0.0.1:18794
      → Ollama 127.0.0.1:11434 / cybernova-security:30b
      → tool_calls Qwen (native или строго валидированный JSON)
      → MCP 127.0.0.1:18792/mcp
      → 6 исходных MCP + 36 локальных, коммуникационных и лабораторных адаптеров

Open WebUI и MCPO не требуются. Нет платного API или прямого shell от модели. Полный набор 87 возможностей ещё не подключён.

## Безопасность и ограничения

- Максимум 12 решений о вызовах и 5 модельных циклов на сообщение; максимум 3 ограниченных публичных GET. Это страховочные лимиты на один запрос, не запрет на виды инструментов.
- На каждом сообщении контроллер запрашивает **актуальный MCP tools/list**, предоставляет Qwen все реально подключённые функции и позволяет **самостоятельно выбирать**, когда и какую вызвать. Ответ без инструментов тоже допустим. Если модель не сформировала native tool_calls, предусмотрен резервный запрос Qwen на строго валидированный JSON-план.
- Пять давно проверенных офлайн/локальных функций выполняются автоматически. Шестая, http_get, автоматически выполняет только HTTPS GET для точных хостов, уже разрешённых в scope.json существующего MCP gateway; сам шлюз ограничивает DNS/TLS/редиректы/частоту/метод.
- **Новые/непроверенные функции не скрыты от Qwen**: модель может выбрать любую из них, но контроллер не исполнит новый вызов до однократного явного подтверждения пользователя. В интерфейсе появится карточка с целью, именем инструмента, параметрами, кнопками «Разрешить один раз» и «Отклонить».
- Подтверждение связано с конкретной сессией, одним точным набором параметров, неизменным определением инструмента и временем жизни 10 минут; после использования нельзя повторно выполнить тот же запрос.
- Если ресурс вне разрешённой области MCP, Qwen получает состояние «нужно расширение scope». Кнопка подтверждения не обходит конфигурацию авторизации; домен добавляет администратор отдельно.
- Инструмент, отсутствующий в tools/list, не подменяется выдуманным вызовом: Qwen должна объяснить, какой адаптер или доступ ей нужен.
- Каталог 87 возможностей исследовательской платформы — **архитектурный план**, а не 87 установленных MCP инструментов. Автоматически становятся доступными только реально объявленные и подключённые функции.
- Предложения 2–3 следующих вопросов создаются отдельным запросом к той же локальной Qwen без инструментов и без сетевых проверок. Клик по вопросу создаёт новое сообщение и только тогда может запустить инструменты.
- Другие 5 инструментов выполняют локальные или офлайн-операции.
- Контекст хранится только в оперативной памяти Python и не сохраняется на диск. После перезапуска диалоги исчезнут.
- Веб-сервер слушает исключительно 127.0.0.1. Приложение пока не поддерживает аккаунты, поэтому открывать его в интернет запрещено. Используйте аутентифицированный SSH-туннель.

## Запуск из отдельной копии ветки feature/cybernova-chat-console

    cd cybernova/research-platform
    python3 -m venv /workspace/cybernova-chat-venv
    /workspace/cybernova-chat-venv/bin/pip install -r console/requirements.txt
    /workspace/cybernova-chat-venv/bin/python -m unittest discover -s tests -v
    /workspace/cybernova-chat-venv/bin/python -m console.server

Сервер поднимется по адресу http://127.0.0.1:18794 на Vast.

На домашнем Windows PowerShell настройте SSH-проброс того же порта, используя реальный endpoint и ключ от Vast:

    ssh -L 18794:127.0.0.1:18794 root@YOUR_VAST_SSH_ENDPOINT

Затем откройте на своём ноутбуке http://127.0.0.1:18794/.

## Автономный тест без сетевых обращений к целям

    cd cybernova/research-platform
    python3 -m unittest discover -s tests -p 'test_*.py' -v
    node --check console/static/app.js
    python3 -m compileall -q console

Acceptance: /api/status показывает реальный Ollama, MCP, подготовленные адаптеры и категории AUTO/ASK/MISSING; Qwen видит весь динамический MCP tools/list, самостоятельно выбирает ip_network_summary для 192.0.2.7/24 и показывает MCP receipt; новый инструмент формирует запрос на одноразовое разрешение и не исполняется до него; scope-запрет не обходится; под ответом появляются тематические вопросы; ошибки исполнения видны пользователю.
