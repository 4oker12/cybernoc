# ADR 001. Исследовательский режим и выполнение инструментов

**Статус.** Принято для локальной Cybernova.

Веб-интерфейс передаёт пользовательский запрос и отображает результат. Access Gateway обслуживает локальный вход, Basic Auth и список разрешённых маршрутов. Console Server управляет диалогом и выполнением задачи. Tool Gateway предоставляет свой каталог и выполнение через MCP. Коммуникационный MCP работает с отдельным интерфейсом задач и сообщений.

| Компоненты | Контракт |
| --- | --- |
| Web UI → Access Gateway → Console | `POST /api/chat/start` принимает `message`, `session_id`, `tools_enabled`, `tool_groups`, `run_id` и случайный `receipt`. Ответ 202 подтверждает принятие. `POST /api/chat/result` с тем же `receipt` возвращает `running`, `completed` с результатом либо `failed` с причиной. |
| Console → модель | OpenAI-compatible адаптер передаёт сообщения и актуальные схемы инструментов. Он принимает текст или вызовы функций. При отсутствии native-вызова на первом шаге совместимый режим может отдельно спросить модель, нужны ли инструменты. Модель может выбрать ноль вызовов. |
| Console → Runtime и MCP | Console проверяет имя и аргументы по каталогу, применяет ограничения и выбирает локальный Runtime или MCP. MCP предоставляет `initialize`, `tools/list` и `tools/call`. Ошибка инструмента возвращается в контекст вместе с идентификатором вызова. |
| Runtime → Chromium | Браузерный сеанс привязан к диалогу и выполняется на выделенном потоке. Patchright запускается первым. Playwright служит резервом при сбое импорта или запуска. Оба движка используют действующие ограничения запросов. |
| Console → интерфейс | Опрос статуса даёт последнее фактическое событие ожидания модели, запуска или завершения инструмента. В итоговом ответе передаются текст, результаты вызовов, `session_id`, `task_id`, номер хода и метрики. |

## Жизненный цикл

1. Console назначает рабочий диалог и связывает ход с задачей. В одной сессии ходы сериализуются.
2. Модель выбирает действие. Console выполняет допустимые вызовы и возвращает наблюдения модели для следующего решения. Последний раунд подводит итог по собранным данным.
3. Console хранит итог асинхронного запроса в ограниченном кеше процесса. Web UI опрашивает его по `receipt`. Повтор старта с тем же `receipt` и RUN ID внутри этого кеша не создаёт ещё одного запуска. При кратком обрыве UI повторяет только запрос статуса.
4. В интерфейсе ожидание ограничено 15 минутами. Шлюз ограничивает отдельный запрос 240 секундами. Истечение клиентского ожидания не отменяет выполнение. Публичного API отмены для этого маршрута пока нет.

## История и восстановление

Сообщения задачи сохраняются в коммуникационном хранилище SQLite. Console восстанавливает ограниченное окно из последних 16 сообщений и может продолжить сохранённую задачу через существующий маршрут возобновления. Внутри хода результаты инструментов входят в контекст модели и компактируются. Между ходами восстанавливается сохранённый диалог с итогами, поэтому конкретный промежуточный результат может выпасть, если он не попал в итог.

Открытая вкладка хранит текущую сессию и ключ опроса в памяти. После перезагрузки вкладки активный опрос автоматически не восстанавливается. Перезапуск Console очищает кеш результатов. Сохранённые сообщения задачи доступны отдельно от этого кеша.
