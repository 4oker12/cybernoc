# Windows: безопасное обновление Cybernova

Рабочая машина: Windows, оболочка пользователя — **CMD**.
Скрипт работает с тем репозиторием, внутри которого он расположен.

## Одна команда в CMD

После получения этой версии репозитория:

```cmd
cd /d "%USERPROFILE%\Cybernova-DeepSeek" && call "tools\windows\Update_Cybernova_Safe.cmd"
```

Что делает обновлятор:
1. `[1/5]` сверяет папку Git, ветку и ожидаемый GitHub origin;
2. `[2/5]` проверяет слушающие порты и показывает владельцев PID (без секретов CLI);
3. `[3/5]` блокирует обновление при локальных изменениях;
4. `[4/5]` получает текущую ветку и выполняет только `git merge --ff-only`;
5. `[5/5]` сверяет хэши и выводит окончательный статус.

Прерывает процесс при ошибке с сообщением `SAFE_UPDATE_FAILED`. Лог сохраняет в
`%LOCALAPPDATA%\CyberNova\logs\safe-update-*.log`.

**Не делает:** не завершает службы/PID, не сбрасывает Git, не удаляет файлы, не
устанавливает зависимости, не перезапускает Runtime и не подключает Vast.

## Если порты заняты

Завершите **только соответствующую Cybernova**, если её PID подтверждён:
`Ctrl+C` в окне, где ранее запускали `native.py ... run`. Если неизвестно,
какой процесс владеет портом, сначала выясните владельца и его функцию. Не
используйте `taskkill /F` для всех `python.exe`.

## После обновления

До нового запуска повторно проверьте порты. Затем используйте штатную команду
`native.py --data-dir "%LOCALAPPDATA%\CyberNova\data" run` из существующей
локальной виртуальной среды и проверьте доступность `http://127.0.0.1:18795/`.

## Первое получение скрипта

Этот файл отсутствует в старых ревизиях. Первое получение изменений выполняйте
из правильной Git-папки **после отдельной проверки портов**, затем в дальнейшем
используйте только обновлятор выше. Не копируйте `git pull` поверх работающей
Cybernova и не полагайтесь на старые инструкции для Vast.
